グーグルドライブ同期の準備

スマホとパソコンなど、いくつかの端末で同じ日記を使うための準備です。1つの端末だけで使うなら、この準備はいりません。

どういうしくみ?
日記の中身は、端末の中で合言葉の鍵をかけてから、あなた自身のグーグルドライブの「アプリ専用の隠しフォルダ」に置きます。 Google にも、このアプリを配った人にも、中身は読めません。
そのために、あなた自身の Google アカウントで「クライアント ID」を1つ作ります(無料。15分ほど)。作るのは最初に1回だけです。

1. Google Cloud で「プロジェクト」を作る

  1. パソコンで https://console.cloud.google.com/ を開き、ふだん使う Google アカウントでログインします。
  2. 上の「プロジェクトを選択」→「新しいプロジェクト」。名前は何でもかまいません(例: diary)。
  3. 作ったプロジェクトが選ばれていることを確かめます。

2. ドライブを使えるようにする

  1. 左のメニュー「API とサービス」→「ライブラリ」。
  2. 「Google Drive API」を探して「有効にする」。

3. 同意画面(ログインのときに出る画面)を作る

  1. 「API とサービス」→「OAuth 同意画面」(画面によっては「Google Auth Platform」)→「開始」。
  2. アプリ名(例: 日記)とサポートのメール(自分のアドレス)を入れます。
  3. 対象は「外部」を選びます。
  4. 「対象」(または「テストユーザー」)で、自分の Google アカウントのアドレスを足します。公開の申請はしません(テストのままで使えます)。
  5. 「データアクセス」(または「スコープ」)で .../auth/drive.appdata を足します(アプリ専用の隠しフォルダだけ。ふつうのドライブのファイルには触りません)。

4. クライアント ID を作る

  1. 「API とサービス」→「認証情報」(または「クライアント」)→「認証情報を作成」→「OAuth クライアント ID」。
  2. アプリケーションの種類は「ウェブ アプリケーション」。
  3. 「承認済みの JavaScript 生成元」と「承認済みのリダイレクト URI」に、日記を開いている場所を入れます。
    入れる文字は、日記の「バックアップ」→「グーグルドライブで同期(鍵つき)」の欄に出ています(そのまま写してください)。
    例: 生成元 https://example.github.io / リダイレクト https://example.github.io/diary/(最後の / まで同じに)
  4. 「作成」を押すと、…apps.googleusercontent.com で終わる「クライアント ID」が出ます。これを写します。

「クライアント シークレット」は使いません。どこにも入れないでください。

5. 日記に入れる

  1. 日記の右上「バックアップ」→「グーグルドライブで同期(鍵つき)」の「Google のクライアント ID」に貼り付けて「同期する」。
  2. Google の画面に移るのでログインします。「Google はこのアプリを確認していません」と出たら、自分で作ったものなので「続行」で進めます。
  3. 最初の端末で合言葉を決めます(8文字以上)。忘れるとドライブの分は誰にも開けません。紙などに控えてください。
  4. 2台目の端末でも、同じクライアント ID を入れて、同じ合言葉を入れます。

うまくいかないとき

  • 「redirect_uri_mismatch」 … 4 で入れたリダイレクト URI が、日記の欄に出ているものと1文字でも違います(/ や index.html の有無も)。
  • 「access_denied」 … 3 のテストユーザーに、ログインしたアカウントが入っていません。
  • ログインが1時間ほどで切れる … そういうしくみです(安全のため)。また「同期」を押せば、ログインし直します。
